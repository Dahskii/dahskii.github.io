KitSmith

Store title: KitSmith by Incline Studio · Planned price: $15 on the Unity Asset Store

A kitbashing level builder for the Unity editor, in the style of Minecraft and survival-game base building. Pick a prefab from your kit, watch the ghost snap to the grid, place it, and keep building. When the level is done, the Organizer and Mesh Combiner clean it up and merge it.

CONSTRUCTOR

Ghost preview placement

A transparent ghost follows your cursor in the Scene view, snapped to the grid. Rotate in 45 or 1 degree steps, raise or lower the build height, and place with one key.

PREFAB ARRAYS

Prefab palettes

Group prefabs into Prefab Arrays and pick from thumbnails in the Inspector. The palette wraps into rows to fit the Inspector width, so big kits stay usable.

ORGANIZER

Organizer

Take pieces already in your scene and assign them to a new parent in one click, with an optional mesh combine on the way in.

MESH COMBINER

Mesh combining

Merge placed pieces into combined meshes, one per material. Ten objects sharing two materials become two draw calls instead of ten.

TEXTURE ATLAS

Combine With Texture Atlas

Packs albedo, normal, metallic, occlusion, and height maps into matching atlases and merges everything into one mesh with one material. One draw call, no matter how many source materials you started with.

UNDO / REDO

Full undo support

Placing, moving, organizing, and combining are each a single Ctrl+Z step. The ghost preview stays out of the undo stack, so undo always hits your last real action.

01Getting started

Drag Prefabs/KitSmith.prefab into the scene. It carries the three components you work with:

  • Constructor: places prefabs and manages the hologram ghost, the snap grid, and rotation.
  • Organizer: assigns selected objects to a parent, copies positions, and creates new parent objects.
  • MeshCombiner: combines meshes, plain or with a texture atlas.
  1. Add the prefabDrag Prefabs/KitSmith.prefab into your scene.
  2. Assign Prefab ArraysCreate a PrefabArray asset for each group of prefabs and assign the assets to the Constructor's Prefab Arrays list. Each group becomes one collapsible section in the palette, with its own color. See Making prefab arrays for the full setup.
  3. Check Color SettingsThe Constructor's Color Settings field takes an Inspector Color Settings asset; one is provided at Settings/InspectorColorSettings.asset. See Inspector colors.
  4. Check key bindingsKey bindings live on the ConstructorSettings asset. See Controls for the defaults.
  5. Start placingClick a prefab in the palette to start its hologram ghost, then press B to place it. See Placing and moving.

Tested configuration: Unity 6000.0.85f2 and 6000.6.4f1 with URP, HDRP, and Built-in. KitSmith lives in Assets/InclineStudio/KitSmith/. The atlas combine is editor-only: it needs TextureImporter access, so it does not run at runtime.

03Placing and moving

  • Click a prefab in the palette to start its hologram ghost, then press B to place it. The ghost is a transient preview: it is never undoable, so Ctrl+Z removes the last real placement, not the preview.
  • To move a placed object, select it and press 1, drag it, then press B to drop it at the new position.
  • Esc while moving cancels the move outright: the object goes back to the position (and layer) it had when you pressed 1, and nothing is deleted.
  • Deselecting the Constructor mid-move restores the object the same way.
  • Use 3 / 4 to raise or lower the grid height. Space resets the grid height. Hold Left Ctrl to ignore raycast while placing.

Tip: The hologram ghost is only visible when Gizmos are turned on in the Scene view. If you pick a prefab from the palette and cannot see the ghost, turn Gizmos on in the Scene view toolbar.

04Rotation axis

C rotates the hologram 45 degrees, V rotates it 1 degree. Both turn it around the current rotation axis:

  • Y (default): turns the piece to face another direction.
  • X: tips the piece forward. Two C presses (90 degrees) lays a wall flat.
  • Z: tips the piece sideways.

The axis is the Rotation Axis field on the Constructor (Y by default). Press X while placing to cycle Y, X, Z, Y, and the field updates to show the new axis. The binding is the Cycle Rotation Axis Key in ConstructorSettings (X by default); C and V stay the rotate keys. Rotation is around the world axes, so X tips a piece forward no matter which way it is facing.

05Making prefab arrays

The palette is built from prefab groups, and each group is a PrefabArrays ScriptableObject asset: one asset per group. You create the asset, fill it with that group's prefabs, then assign it to the Constructor. Work through these steps once for each group you want in the palette:

  1. Create the assetIn the Project window, right-click and choose Create > InclineStudio > PrefabArray. A new PrefabArray asset appears in the folder you right-clicked in.
  2. Name it after the groupThe asset's name becomes the group name shown in the palette, so rename the asset to the name you want on the group's header, for example "Walls" or "Furniture".
  3. Fill the Prefabs listSelect the asset to open it in the Inspector and find its Prefabs list. Set the list size to the number of prefabs in this group, then drag each prefab into a slot in the list.
  4. Assign it to the ConstructorSelect the KitSmith object in the scene and find the Constructor's Prefab Arrays list. Add an entry to the list, then drag the PrefabArray asset into that entry.
  5. Repeat for each groupMake one asset per group and add each one to the Prefab Arrays list. Every group gets its own collapsible section in the palette, under its asset's name, and its own color from the group color list (see Inspector colors).

A typical setup is a handful of assets, one per kind of piece: one for walls, one for floors, one for props, and so on. Each asset holds only its own group's prefabs, so adding a piece later is just adding it to the right asset's Prefabs list, and adding a whole new group is one more asset and one more entry in the Prefab Arrays list.

Empty slots are fine: an empty entry in the Constructor's Prefab Arrays list is tolerated, so you can add entries ahead of time or leave a slot blank without breaking the palette. The groups that do have an asset assigned show up as normal.

06Prefab palette

The palette shows one button per prefab, grouped under collapsible group headers. Each group is a PrefabArray asset assigned to the Constructor (see Making prefab arrays).

  • Each button caches its prefab's preview image the first time it is asked for, and the Inspector repaints while any preview is still generating, so the images pop in instead of sitting on "Loading...".
  • While a preview is loading the button shows the prefab's name, so it is always clickable and identifiable; once the image is ready the button shows it (hovering shows the name as a tooltip).
  • Each image is copied into a texture the editor owns as soon as it arrives, because Unity's preview cache evicts images when too many are in flight (large groups, several groups open): without the copy the button flips back to the prefab name whenever its image is evicted.
  • Every prefab gets exactly one stable button no matter what the previews are doing, and group numbering no longer desyncs, so a click spawns the prefab on the button you pressed.

07Organizer

The Organizer works with objects already in your scene:

  • Copy Position: copies the selected object's position to the clipboard value.
  • Create New Object: creates a new parent object.
  • Assign To Object: parents the selected objects to the chosen object, restoring parenting, position, and name on undo. With Combine Meshes on, it also combines their meshes (same as the MeshCombiner's plain combine).

If the target already has a combined mesh, adding more pieces merges that old mesh into the new combine instead of deleting it, the same as the MeshCombiner.

08Inspector colors

The inspector is colorful: the whole inspector sits on the inspector background color, the "Prefab Groups" header takes the header color, each group header takes its own color from the group color list (cycling back to the first color when there are more groups than colors), and the palette area behind the buttons takes a pale tint of the group color on the light theme or a dark tint on the dark theme, so the images and names stay readable either way. Each prefab button is the plain Unity button, with a 2 pixel frame in the button border color around it.

The Organizer and Mesh Combiner inspectors use the same colors: they sit on the inspector background color too, their action buttons sit on a pale or dark tint of the header color, and each button gets the same border frame.

Readability: the background color only colors the panel behind the controls, never the controls themselves: toggles, sliders, and fields keep their normal look whatever color and alpha the background is set to, so they stay readable on a dark or translucent background.

Changing the colors

The colors live in the Inspector Color Settings asset (Settings/InspectorColorSettings.asset), already assigned to the Constructor's Color Settings field. To change them, edit the asset:

  • inspectorBackgroundColor for the whole inspector
  • headerColor for the section header
  • groupColors for the per-group cycle (add or remove entries to taste)
  • buttonBorderColor for the frame around each prefab button

To turn colors off, uncheck colorsEnabled on the asset and the inspector goes back to plain. To use a different set of colors, create a new one (right-click in the Project window, Create, InclineStudio, Inspector Color Settings) and drag it onto the Constructor's Color Settings field.

The Organizer and Mesh Combiner need no assignment of their own: they use the Constructor's color settings when one is on the same object, otherwise the project's Inspector Color Settings asset, and the built-in default colors when there is none. A Constructor with no color settings assigned resolves the same way. Pick mid-tone colors: very dark or very light colors can be hard to read in the opposite theme.

09Undo / Redo

One Ctrl+Z undoes one whole action, and Ctrl+Y redoes it:

ActionUndo step
Place a prefab with the build key (B)Removes the placed object (prefab link kept)
Move a selected object (key 1, then B to drop)Restores the original position AND the original layer. The move is recorded once at the start of the drag, so it is a single step.
Organizer: Assign To ObjectRestores parenting, position, and name for the whole assign
Organizer: Create New ObjectRemoves the created object
Organizer: Copy PositionRestores the previous position value
Mesh combine (both modes)Restores the originals (re-activates them) and removes the combined object(s)

Deliberately NOT undoable: the hologram ghost. It is a transient preview, created with a plain Instantiate and killed with DestroyImmediate. Registering it would make Ctrl+Z delete the preview instead of the last real placement.

10Mesh combine

MeshCombiner has two buttons: Combine and Combine With Texture Atlas.

  • Combine: one combined mesh per distinct material, so multi-material selections keep their look instead of collapsing onto the first object's material.
  • Combine With Texture Atlas: packs every source map into its own atlas, then combines everything into ONE mesh with ONE material. One draw call no matter how many source materials there were. See the next section.

Both modes show a progress bar while they work (collecting, packing, building each atlas, remapping UVs, saving, combining), which clears when the combine finishes.

In both modes the combined mesh is always a new child of the Parent Object (named Combined (...) / Combined Atlas), never the parent or root object itself. And if the parent already has a combined mesh, adding more pieces merges that old mesh into the new combine instead of deleting it. Same for Organizer's Assign To Object with Combine Meshes on.

11Texture atlas combine

Options on the MeshCombiner component:

OptionWhat it does
Atlas Size2048 by default. The atlas grows automatically (doubling, up to 8192) when the textures would otherwise be packed smaller than their source, so a detailed texture keeps its full resolution instead of smearing; the combine summary line reports the final size. Every map atlas is this size, so a full set (albedo + normal + metallic + occlusion + height) is five textures of this size in memory.
Atlas Padding2 px between packed textures. Raised to at least 8 automatically when any source has a height map, so parallax samples stay inside their tile.
Save Atlas AssetsOn by default. Saves the atlas textures (.assets, so their exact packed pixels survive a reload with no PNG re-import or recompression) and the atlas .mat under Assets/InclineStudio/KitSmith/GeneratedAtlases/ (named after the parent object, unique names if one already exists), so the combined mesh keeps working after a reload. The saved atlases are stored uncompressed (no DXT1) so fine detail like grid lines is not smeared by block compression, and they keep their mipmaps so a surface seen from a distance stays crisp instead of aliasing into a smear (the packing padding keeps any mipmap bleed to the tile edges), and they use anisotropic filtering (level 8) so a floor seen at a shallow angle keeps its grid lines sharp on the far side instead of squishing together. Turn it off and the atlases only live in memory for this session.
Assets/InclineStudio/KitSmith/GeneratedAtlases/

How it works

Each distinct source material (its maps plus the scalars baked into them) becomes one tile. The albedo tiles are packed with Texture2D.PackTextures; every other map atlas is built into the SAME tile layout, so one set of remapped UVs samples all of them. Each source mesh is copied (the original shared mesh is never mutated), its UVs are remapped into its tile, and all remapped meshes are combined into one mesh. Material colour is baked into the albedo tile, and the atlas material itself is white, on the pipeline shader for your project (URP Lit, HDRP Lit, or Standard). Source textures that are not readable are made readable (via the TextureImporter) or copied through a RenderTexture.

One atlas per map type

One atlas is built per map type, and only when some source has that map (or a scalar that needs baking):

AtlasFile / propertyHow it is built
Albedo_Atlas.asset, _BaseMapFound by property scan, so a map carried on a standard or non-standard property name is still picked up. Colour baked into the tile.
Normal_Atlas_Normal.asset, _BumpMapFound by property scan, like the albedo. Saved as a linear normal map (never sRGB), with bump scale baked into the normals, so the atlas material runs _BumpScale at 1. Materials with no normal map get a flat-normal tile. A compressed normal map is unpacked from the layout it actually stores (DXT5nm keeps X in alpha and Y in green), so a normal atlas tile stays blue like its source instead of coming out pink.
Metallic_Atlas_Metallic.asset, _MetallicGlossMapR = metallic, A = smoothness. Sources: _MetallicGlossMap (R metallic, A smoothness), URP _MaskMap (R metallic, A smoothness), or a packed occlusion / roughness / metallic map (its B channel). Metallic and smoothness scalars are baked in, so the atlas material runs _Metallic / _Smoothness at 1. Materials with no metallic data get a solid tile from their scalars (metallic 0, smoothness 0.5 by default).
Occlusion_Atlas_Occlusion.asset, _OcclusionMapURP samples the green channel. Sources: _OcclusionMap, _MaskMap (G), or a packed occlusion / roughness / metallic map (its R channel). Occlusion strength is baked in, so the atlas material runs _OcclusionStrength at 1. Materials with no occlusion data get a white tile.
Height_Atlas_Height.asset, _ParallaxMapURP parallax samples the green channel with 0.5 as zero offset, so the parallax scale is baked in as h' = 0.5 + (h - 0.5) * scale and the atlas material runs _Parallax at 1. Only built when a source has a height map with a non-zero parallax scale. Materials with no height map get a mid-grey tile.

Tangents

The combined mesh gets its tangents recalculated whenever a normal map is in use, by default. Some models are imported with tangents set to None, so a combine can mix sources that carry tangents with sources that do not, and the combined mesh ends up with a tangents array that is only good for some of its vertices. Recalculating from the final (atlas-remapped) UVs gives every vertex a correct tangent, and it also replaces any stale authored tangents that were made for the original UVs. Without it, a model imported without tangents can go dark as soon as a normal map is applied, even though it looks fine with bump scale at 0.

Custom shaders and packed maps

Materials on custom shaders are handled by the same scan: if a shader carries its albedo or its normal map on a non-standard property name, the scan still finds those maps and atlases them instead of dropping them. A packed map that stores several channels in one texture is split into its channels for the matching atlases: R = occlusion, G = roughness, B = metallic, with smoothness taken as 1 minus roughness. Scalar values that multiply those channels, and the shader's bump strength, are baked into the tiles the same way the standard scalars are, so the combined result keeps the material's original look as closely as the single atlas material allows.

HDRP

In an HDRP project the atlas material is HDRP Lit, which has different property names and no separate metallic or occlusion map, so the combine adapts:

  • Albedo goes on _BaseColorMap, normals on _NormalMap (with _NormalScale at 1).
  • Metallic, occlusion, and smoothness are combined into one _Atlas_Mask.asset on _MaskMap: R = metallic, G = occlusion, B = detail mask (set to 1, no detail map on the atlas material), A = smoothness. The mask channels are used as-is by HDRP Lit, and _Metallic / _Smoothness stay at their defaults (0 / 0.5) because HDRP only uses those floats when no mask map is assigned.
  • Height is dropped in HDRP (with a console warning): HDRP Lit has no parallax mapping. Its _HeightMap is for tessellation displacement, which the combine does not set up.
  • HDRP's metallic / smoothness / occlusion remap min/max ranges are not baked (they stay at 0..1 on the atlas material), and detail maps are dropped.

HDRP status: Tested in an HDRP project. The console line reads "maps: albedo + normal + mask" and GeneratedAtlases contains _Atlas.asset, _Atlas_Normal.asset, _Atlas_Mask.asset, plus the .mat. The combined mesh keeps its bump and its metallic / matte look.

12Limits — read before you ship a level on this

  • Only the maps above are atlased. Emission maps are dropped. Smoothness sourced from the albedo alpha channel is not carried over; the atlas material takes smoothness from the metallic map's alpha.
  • Custom-shader materials work too: the atlas finds each material's maps by scanning its texture properties, so a shader that carries its albedo on a non-standard property name still gets its textures atlased instead of going flat. But the custom shader itself is replaced by the single atlas material, so its shader effects are dropped: the textures show with plain UV mapping, and alpha cutout is dropped.
  • Texture tiling is baked into the UVs and then wrapped into [0,1] (WrapAtlasUV), so a repeating texture keeps repeating across the face instead of stretching its edge pixels. An exact UV of 1.0 is kept on the tile edge, not wrapped to 0: Mathf.Repeat maps 1.0 to 0.0, which teleported the edge vertices of a mesh whose UVs reach 1.0 (a 3-unit floor piece) to the opposite edge of the tile and stretched and mirrored its outer strip 2x. A material that relied on Clamp with UVs outside 0-1 will wrap instead of clamping to its edge pixels.
  • Two materials sharing one texture but with different colours get different tiles (colour is baked into the tile), and two materials sharing all maps but with different baked scalars (metallic, smoothness, bump scale, ...) get different tiles too.
  • Meshes with no UVs sample the atlas corner.
  • Editor-only. It needs TextureImporter access, so it does not run at runtime.
  • Multi-material meshes are handled per submesh; each submesh goes into the atlas under its own material.

13Code summaries

A reference for every script in the package, with a summary of what each one does. Paths are relative to Assets/InclineStudio/KitSmith/. The two core scripts, Constructor.cs and MeshTools.cs, also list their key methods.

Scripts/Constructor.cs

The Constructor class is the central component of KitSmith. It manages the placement and manipulation of prefabs in the Unity Editor and organizing GameObjects in the hierarchy. The file also defines the RotationAxis enum: the axis RotateHologram turns the hologram around. Y is the default (turn a piece to face another direction); X tips it forward, Z tips it sideways, so a wall can be laid flat or a floor stood on its edge.

Key methods:

  • StartConstructor: activates the constructor.
  • StopConstructor: deactivates the constructor.
  • WatchSceneFocus: destroys the hologram ghost whenever keyboard focus leaves the Scene view, so a ghost left alive across focus changes cannot misbehave.
  • Run: the main method for running the constructor logic: raycasting and hologram placement.
  • SnapToGridAtCursor: snaps the hologram to the grid based on the cursor's position.
  • SnapToGrid: snaps a position to the nearest grid point.
  • RotateHologram: rotates the current hologram by a specified amount around the selected rotation axis.
  • CycleRotationAxis: cycles the rotation axis through Y, X and Z in that order.

Scripts/ConstructorSettings.cs

The ConstructorSettings class is a ScriptableObject that holds configurable key bindings and settings for the Constructor. It lets users customize key bindings for various actions in the constructor system.

Scripts/DisplayNameAttribute.cs

The DisplayNameAttribute class is a custom attribute that allows specification of a display name for components, applied to classes (particularly MonoBehaviour-derived classes) to provide a custom name in the editor.

Scripts/Editor/ConstructorEditor.cs

The ConstructorEditor class is a custom editor for the Constructor. It provides a specialized interface in the Unity Editor for managing prefabs and controlling the Constructor functionality, including the prefab palette, preview images, and the hologram.

Scripts/Editor/KitSmithColors.cs

The KitSmithColors class is the shared color access for the KitSmith inspectors. It finds the Inspector Color Settings asset (no assignment needed on the component), hands out the colors with the built-in defaults as the fallback, and draws the colored panels and bordered buttons.

Scripts/Editor/MaterialPipelinePostprocessor.cs

The MaterialPipelinePostprocessor class converts KitSmith's materials to the active render pipeline on import. It maps between Built-in (Standard), URP (Universal Render Pipeline / Lit) and HDRP (HDRP / Lit), preserving color, main texture and smoothness.

Scripts/Editor/OrganizerEditor.cs

The OrganizerEditor class is a custom inspector interface for the Organizer component. It enhances the default inspector with additional functionality specific to object organization and mesh combining.

Scripts/Editor/Utilities.cs

The Utilities class is a static class that provides common utility functions used across the KitSmith system, designed to be reusable.

Scripts/Hologram.cs

The Hologram class is used as a placeholder for visualizing where a prefab will be instantiated in an in-editor build system. It allows for the placement and preview of prefab objects directly within the Unity Editor.

Scripts/InspectorColorSettings.cs

The InspectorColorSettings class is a ScriptableObject that holds the colors for the KitSmith inspector. Edit the asset to change the colors; turn colorsEnabled off to go back to the plain inspector. Assign a different color settings asset to the Constructor to use a different set of colors.

Scripts/MeshTools/Editor/MeshCombinerEditor.cs

The MeshCombinerEditor class is a custom inspector interface for the MeshCombiner component, enhancing the default inspector with functionality specific to mesh combining.

Scripts/MeshTools/MeshCombiner.cs

The MeshCombiner class is a component that combines multiple GameObjects' meshes into a single mesh, useful for optimizing the scene by reducing the number of draw calls. It has two combine modes: Combine (one combined mesh per material) and Combine With Texture Atlas (one mesh, one material).

Scripts/MeshTools/MeshTools.cs

The MeshTools class provides utilities for combining multiple meshes into a single mesh, useful for optimizing scene rendering by reducing draw calls. Every mutation in both combine paths is registered with Undo.

Key methods:

  • CombineMeshes: combines the meshes of the specified GameObjects into single meshes, grouped by material, one combined mesh per distinct material so multi-material selections keep their look.
  • CombineMeshesWithAtlas: combines them into one mesh with one material, packing every source texture into a single atlas texture first.
  • TryGetAlbedoTexture: finds the material's albedo texture, whatever property the shader puts it on, preferred names first then a scan of every texture property.
  • TryGetMapTexture: finds a map texture on the material: preferred property names first, then any texture property whose name contains one of the given parts.
  • CollectMaterialMaps: everything the atlas path needs from one source material, as one tile key: the albedo texture and the colour baked into its tile, every other map the material has, and the scalars.
  • BuildMapAtlas: builds one map atlas into the same tile layout as the albedo atlas so the one set of remapped UVs samples every atlas at the same tile.
  • CopyTileIntoAtlas: copies one source texture into a rect of an atlas, scaling it to the rect size.
  • UnpackNormalMapPixel: rebuilds one tangent-space normal from the layout a compressed normal map actually stores; a DXT5nm map keeps X in alpha and Y in green.
  • GetScaledTilePixels: reads one source texture scaled to a size, straight from its pixels with a CPU bilinear resize, keeping the source orientation.
  • ApplyBumpScale: scales a normal map's X/Y by the bump scale and renormalizes it, so the atlas material can run _BumpScale at 1.
  • ApplyParallaxScale: bakes the parallax scale into a height value.
  • WrapAtlasUV: wraps a texture-scaled UV into [0,1] for its atlas tile, so a tiling material repeats instead of stretching; a UV already inside [0,1] is left alone.
  • SaveAtlasAssets: saves every atlas texture as a .asset and the atlas material as a .mat, under Assets/InclineStudio/KitSmith/GeneratedAtlases.
  • ShowCombineProgress / ClearCombineProgress: show and hide the combine progress bar; editor-only, a no-op in a build.

Scripts/Organizer.cs

The Organizer class organizes GameObjects in the Unity hierarchy. It assigns selected GameObjects to a specific parent, and optionally combines their meshes into a single mesh for optimization.

Scripts/PrefabArrays.cs

The PrefabArrays class is a ScriptableObject that groups prefabs together. It stores collections of prefabs and their associated UI foldout states in the Unity Editor, for organizing and using these prefab groups when instantiating objects from a hologram in the editor. Its prefabs array holds the GameObject prefabs used by the hologram instantiation system.
